# v0.1.1 Release Repair Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the withdrawn v0.1.0 desktop release with a signed, notarized,
clearly named v0.1.1 release containing installers only.

**Architecture:** Each matrix job builds without publishing, verifies its target,
and copies an exact allowlist of installers into a staging directory. A single
dependent job downloads those staging artifacts and uploads them to one draft
GitHub Release. macOS is fail-closed on credentials and distribution checks.

**Tech Stack:** GitHub Actions, electron-builder, Node.js 22, node:test, pnpm 11,
codesign, spctl, and Apple notarytool/stapler.

**Spec:** `docs-internal/specs/2026-08-30-v0.1.1-release-repair.md`

## Global Constraints

- Changes merge to `dev` before `main`.
- v0.1.0 remains immutable and withdrawn; repaired artifacts use v0.1.1.
- GitHub Releases receive only DMG, ZIP, EXE, AppImage, and deb installers.
- Every installer filename includes `macos`, `windows`, or `linux` and `arm64`
  or `x64`.
- macOS artifacts cannot be staged unless signing and notarization validation
  succeeds.

### Task 1: Installer allowlist

**Files:**
- Create: `apps/desktop/scripts/collect-release-installers.mjs`
- Create: `apps/desktop/scripts/test/collect-release-installers.mjs`
- Modify: `apps/desktop/package.json`

**Interfaces:**
- Consumes: `--platform`, `--arch`, `--version`, `--dist`, and `--out` arguments.
- Produces: a clean staging directory containing only the expected installers.

- [ ] **Step 1: Write the failing artifact-policy test**

Create fixtures containing the exact expected installers plus `latest.yml` and
`.blockmap` files. Assert the collector copies only the installer allowlist and
fails when an expected installer is missing or misnamed.

- [ ] **Step 2: Verify the test fails**

Run:
`node --test apps/desktop/scripts/test/collect-release-installers.mjs`

Expected: failure because `collect-release-installers.mjs` does not exist.

- [ ] **Step 3: Implement the collector**

Use an explicit map:

```js
const extensions = {
  mac: ["dmg", "zip"],
  win: ["exe"],
  linux: ["AppImage", "deb"],
};
const osName = { mac: "macos", win: "windows", linux: "linux" }[platform];
const expected = extensions[platform].map(
  (ext) => `PromptBranch-${version}-${osName}-${arch}.${ext}`,
);
```

Reject unknown platforms/architectures, require every expected file, empty the
staging directory, and copy only expected files.

- [ ] **Step 4: Verify focused tests pass**

Run the node test above and `pnpm --filter @promptbranch/desktop test:release-assets`.

- [ ] **Step 2: Verify the workflow test fails for the old unsigned workflow**

`node --test apps/desktop/scripts/test/verify-desktop-release-workflow.mjs`

Expected: failures for direct publishing, unsigned macOS, and missing publisher.

Set per-platform `artifactName` values:

```json
"mac": { "artifactName": "PromptBranch-${version}-macos-${arch}.${ext}" },
"win": { "artifactName": "PromptBranch-${version}-windows-${arch}.${ext}" },
```

- [ ] **Step 4: Make macOS signing fail closed**

Expose `CSC_LINK`, `CSC_KEY_PASSWORD`, `APPLE_ID`,
`APPLE_APP_SPECIFIC_PASSWORD`, and `APPLE_TEAM_ID` only to macOS build steps.

`CSC_IDENTITY_AUTO_DISCOVERY=false` from macOS.

- [ ] **Step 5: Add distribution validation**

successful `hdiutil verify` on the container plus `codesign --verify --deep
--strict`, `spctl -a -vv --type execute`, and `xcrun stapler validate` on the
app payload.

- [ ] **Step 6: Publish from one dependent job**

All matrix builds use `--publish never`, run the collector, and upload only its
output. A `publish-release` job uses pinned `actions/download-artifact@v8.0.1`,
creates or updates a draft release, and uploads the ten allowlisted installers.

`pnpm --filter @promptbranch/desktop test:release-assets`
